OVERVIEW                                      *markdown-table-wrap-overview*

markdown-table-wrap.nvim renders Markdown pipe tables with wrapped cell
content. Automatic rendering does not modify the source Markdown buffer; the
explicit Source-aware Reader cell mappings are the guarded editing exception.
The default display mode is a full-document Reader. Source-position-preserving
inline replacement and a floating preview remain available as optional modes.

READER MODE

Reader mode mirrors the document into a protected scratch buffer and replaces
every supported top-level pipe table with real Unicode buffer lines. Rendering
never modifies the source Markdown buffer. With auto_preview enabled, the default
reader.auto_open value "has_table" opens Reader only after a table is
detected.
Plain Markdown remains in Source. Set reader.auto_open to "always" to open
Reader for every supported buffer.

Unlike inline extmark replacement, reader mode is not layered over long raw
table rows. Native wrap therefore cannot reveal source pipes or URLs beneath
the rendered table.

Rendered table rows are also protected from a second Markdown syntax pass.
Literal underscores and angle brackets inside rendered code keep their display
width and cannot move table borders. The underlying Reader rows remain real
text for search, selection, and yank.

Cell wrapping uses Neovim display width. Inline-code spans remain intact when
they fit their allocated column; if a code token is wider than that column, it
is split at character boundaries so narrow Reader and Inline tables keep their
vertical borders aligned.

Default interaction:

- Normal mode stays in Reader.
- v/V/CTRL-V select real rendered lines. Yank keeps Reader active.
- Inside a rendered table cell, |markdown-table-wrap-yic| yanks the original
  Markdown source, |markdown-table-wrap-vic| selects the complete logical cell
  across wrapped lines, |markdown-table-wrap-dic| clears only that cell,
  and |markdown-table-wrap-cic| changes it in Source Insert. After vic, y/d/c/p
  apply to the same raw Source cell. Neovim's native Source operators own
  register and one-step undo behavior. Dot repeats the last successful cell
  mutation while Source is unchanged; undo followed by redo preserves logical
  repeat. Counts greater than one are rejected without changing Source. These
  operations preserve the row's other cells and pipe delimiters.
- Reader reserves Normal-mode y and d for the complete configured cell
  sequences. By default, any mismatch such as yj, yk, yap, dj, dk, or dd is
  cancelled without moving the cursor, changing registers/Source, copying
  rendered borders, or raising E21. Use native v/V/CTRL-V followed by y to
  copy rendered text, or edit Source for structural deletion.
- |markdown-table-wrap-cip| is an opt-in compatibility mapping because cip is
  Vim's native ci-paragraph sequence. |:MarkdownTablePutCell| provides cell put
  without consuming that default key.
- |markdown-table-wrap-cell-change| proxies Vim's native Source c operator.
  cic is resolved first as the cell operation; cip, ciw, cw, c$, and other
  motions leave Reader and continue in Source. Inside a table row, native cip
  normally changes the whole contiguous table paragraph; use cic for one cell.
- Native v/V/CTRL-V behavior is unchanged. Reader adds a visible Visual
  overlay so selections remain obvious on rendered table cells; the overlay
  does not change what native Visual mode selects.
- i/a/I/A/o/O switch to the corresponding source line for editing. Reader
  reopens after InsertLeave.
- :w, :wq, :x, and ZZ save the backing Markdown source directly. The rendered
  Reader buffer is never written to disk; :wq then quits as usual.
- |:MarkdownTableToggleReader| switches between Reader and Source.
- |:MarkdownTableEditSource| leaves Reader and pauses automatic reopening.
- gx in Reader opens the original target under a rendered link. Away from a
  target it delegates to the Source mapping captured when Reader opened, or to
  native gx when available. Source-buffer gx is left untouched by default;
  native buffer/window navigation dismisses Reader without pausing Source, so
  returning to an auto-preview Source restores Reader at the previous cursor
  and window scroll. Explicit close/edit or disable actions keep their
  persistent pause semantics.
  see |markdown-table-wrap-map-gx|.

CELL OPERATIONS                              *markdown-table-wrap-cell-operations*

The Reader cell mappings operate on one logical table cell even when the
rendered value occupies several wrapped Reader lines. Markdown semantics are
always taken from the exact Source range, never reconstructed from displayed
text:

  yic  *markdown-table-wrap-yic*          Yank the raw Source cell with native
                                          selected-register behavior.
  vic  *markdown-table-wrap-vic*          Enter Visual mode over every rendered
                                          segment of the logical cell.
  dic  *markdown-table-wrap-dic*          Clear only the Source cell content
                                          with native delete-register behavior.
  cic  *markdown-table-wrap-cic*          Change the Source cell as one undo
                                          block and enter Insert mode; Reader
                                          normally reopens after InsertLeave.
  .                                       Repeat the last successful Source-cell
                                          delete, change, or put while Source
                                          remains unchanged.
  cip  *markdown-table-wrap-cip*          Optional compatibility mapping for
                                          Source-cell put. It is disabled by
                                          default; native cip remains change
                                          inner paragraph. Prefer
                                          :MarkdownTablePutCell for cell put.
  c    *markdown-table-wrap-cell-change*  Leave Reader and continue Vim's
                                          native Source change operator. cic is
                                          resolved first as the cell operation.

Reader is a derived, non-modifiable buffer, so its Normal-mode y and d are
guarded prefixes rather than native operators over rendered rows. The plugin
consumes the configured suffix and runs only an exact match (yic/dic by
default); Esc or a mismatch cancels without touching the cursor, registers,
Source, or Reader. This prevents yj/yk from copying borders and prevents
dj/dk/dd from raising E21. vic still resolves v + ic in Visual mode. cic
retains its complete Normal-mode alias while the Source c proxy is installed;
any other c motion is deliberately replayed against Source. An explicitly
configured cip instead claims c + ip for cell put. After vic, temporary
y/d/c/p mappings act on the raw Source cell and restore any previous Visual
mappings when the logical selection ends. Native v/V/CTRL-V followed by y
continues selecting and copying rendered Reader text.

The mappings are enabled by default and can be changed under
|markdown-table-wrap-mappings|. Set mappings.reader.cell to false or
{ enabled = false } to disable them. Mutations are intentionally limited to a
single physical Source line and refuse synthetic missing cells, so a malformed
row is never rewritten implicitly.

VIEW CHOICE                                  *markdown-table-wrap-view-choice*

Use Source for structural editing such as dd, Visual changes, moving rows, or
changing table delimiters. Use Inline when editing the original buffer while
keeping a rendered table layer visible. Use Reader for stable full-document
reading; its i/a/o/e editing commands jump to the mapped Source line.

|:MarkdownTableToggleInline| switches between Source and Inline. From Reader
it first returns to Source and then enables Inline. Press it again to clear
Inline and leave Source visible.

For arbitrary source structure, toggle to Source and use normal Visual mode.
For a logical table cell, use the Source-aware Reader mappings above.

When optional inline mode is selected, complete-table rendering remains the
default and viewport slicing remains disabled.

If you enable |markdown-table-wrap-inline-viewport-scrolling|, the plugin
instead keeps inline rendering inside the original source table height and
lets you move through the rendered slice with |:MarkdownTableScrollDown|,
|:MarkdownTableScrollUp|,
|:MarkdownTableScrollTop|, and |:MarkdownTableScrollBottom|.

The plugin is designed to coexist with render-markdown.nvim by letting
render-markdown.nvim handle non-table Markdown while markdown-table-wrap.nvim
owns pipe table rendering.

Requirements:

- Neovim 0.10+
- No external binary dependencies

INSTALLATION                                  *markdown-table-wrap-installation*

Example lazy.nvim / LazyVim spec:
>
  return {
    {
      "ice345/markdown-table-wrap.nvim",
      ft = { "markdown", "quarto", "rmd" },
      opts = {},
    },
  }
<

For local development:
>
  return {
    {
      dir = "~/Code/lazyvim-table/markdown-table-wrap.nvim",
      ft = { "markdown", "quarto", "rmd" },
      opts = {},
    },
  }
<

Example LazyVim key bindings:
>
  keys = {
    {
      "<leader>mr",
      "<cmd>MarkdownTableToggleReader<cr>",
      desc = "Toggle Markdown reader/source",
    },
    {
      "<leader>mi",
      "<cmd>MarkdownTableToggleInline<cr>",
      desc = "Toggle Markdown table inline view",
    },
    {
      "<leader>me",
      "<cmd>MarkdownTableEditSource<cr>",
      desc = "Edit Markdown source",
    },
  }
<

ToggleReader is bidirectional. EditSource is one-way and pauses automatic
reopening until Reader is explicitly opened again. ToggleInline selects Inline
for the current buffer's editing session without changing global setup.

Session files should restore Source rather than the disposable Reader or Float
scratch buffer. After setup, auto_preview and reader.auto_open may recreate a
view. The plugin does not serialize scratch view buffers into the session.

Important options:

max_width_ratio~
    Maximum rendered table width as a ratio of the current window width,
    clamped to 0.1 through 1.0.

min_col_width~
    Minimum display width for a column.

max_col_width~
    Maximum natural display width before wrapping.

fit_to_window~
    Prioritize keeping the complete table inside the current window text area.
    When necessary, columns may become narrower than min_col_width.

preview_mode~
    "reader" (default), "inline", or "float".

reader~
    Behavior for the full-document reader. reader.auto_open accepts
    "has_table" (the default) or "always". "has_table" automatically enters
    Reader only after a table is detected, so plain Markdown stays in Source.
    "always" enters Reader for every supported buffer.

    By default ordinary Markdown in Reader uses wrap and breakindent, while
    linebreak remains disabled. Table rows are already wrapped by the plugin
    and stay inside the computed text width.

    reader.sticky_header defaults to false. When enabled, the current table's
    rendered header is shown in the window winbar while the cursor is inside
    that table. This is visual-only; Reader lines, search, yank, and copied
    text are unchanged, and the previous winbar is restored outside the table
    and when Reader closes.

inline_mode~
    "replace" hides source text and overlays rendered rows.
    "insert" shows rendered rows above or below the source table.

inline_virtual_text~
    "overlay" or "win_col" for the replace-mode virtual text strategy.
    "overlay" is the default and is generally the most portable choice.

inline_disable_wrap~
                                *markdown-table-wrap-inline-disable-wrap*
    Enables the temporary nowrap protection for inline replace mode. Long
    concealed source rows can otherwise soft-wrap underneath the rendered
    table on some terminal and platform combinations.

inline_wrap_scope~
    Controls where |markdown-table-wrap-inline-disable-wrap| applies:

    "always" disables wrap for the whole window while inline tables are
       active. This is the strictest and most stable setting.

    "cursor" (the default) disables wrap only while the cursor is inside a
    rendered table, then restores the previous window-local wrap setting so
    ordinary Markdown paragraphs continue to wrap normally.

    "never" leaves wrap fully under user control. This may allow concealed
    source rows to leak or flicker on long tables.

clear_on_visual~
    In inline mode, reveal source Markdown while selecting text and re-render
    after leaving Visual mode. Reader mode selects real rendered lines and
    stays active after yank.

auto_preview~
    Automatically render supported buffers. In Reader mode, automatic opening
    also follows reader.auto_open.

render_all~
    Render all tables in the current Markdown buffer.

discovery~
    Select the table-range discovery backend: "auto", "lua", or
    "treesitter". Auto currently uses the guaranteed Lua scanner. Explicit
    Tree-sitter discovery falls back to Lua if a compatible parser or table
    node is unavailable. The requested backend, selected backend, and fallback
    reason are shown by |:MarkdownTableInspect|.

cache~
    cache.enabled defaults to true. Parsing is keyed by Source changedtick;
    layout additionally uses window width and relevant configuration. Buffer
    wipe releases every owned entry. See docs/performance.md in the repository
    for the benchmark and reference resource budgets.

highlight_preset~                  *markdown-table-wrap-highlight-preset*
    "default", "tokyonight", "catppuccin", "render_markdown", "auto", or a
    custom key supplied through |markdown-table-wrap-themes| or
    |markdown-table-wrap-theme-dir|. The default preset links to standard
    Neovim highlight groups so it works naturally with arbitrary colorschemes.

theme_dir~                              *markdown-table-wrap-theme-dir*
    Optional directory containing custom theme files named <preset>.lua.

themes~                                    *markdown-table-wrap-themes*
    Inline custom theme table keyed by |markdown-table-wrap-highlight-preset|.
    For example, set highlight_preset = "my_theme" and provide
    themes.my_theme.

inline_viewport_scrolling~
                         *markdown-table-wrap-inline-viewport-scrolling*
    When enabled, |:MarkdownTableScrollDown| and |:MarkdownTableScrollUp|
    page through rendered rows inside the original table height.

    When disabled, the complete rendered table is shown inline with extra
    virtual lines. This is the default because it is less surprising on first
    use. In that mode, scroll commands fall back to normal window scrolling
    because the table is already expanded visually.

wide_table~                         *markdown-table-wrap-wide-table*
    Optional policies for wide tables. The default mode is "wrap", preserving
    the existing fit-and-wrap layout. Set mode = "viewport" to render a
    contiguous column slice with a marker (default …) on each hidden side.
    viewport.start_column and viewport.column_count choose the slice; the
    :MarkdownTableViewportLeft/Right commands move it. columns[n] accepts
    width (fixed), min, max, weight, and priority. Fixed widths are retained;
    when constraints cannot fit, layout.overflow is true in the rendered model
    and the best-effort result is deterministic. allocate_extra = true uses
    weight to distribute spare width.

link~
    Icon configuration for links, wiki links, images, and URL pattern matches.
    link.resolver may be a function(target, context, strategy). Return true or
    "noop" when handled, false to cancel, or "edit", "split", "vsplit", or
    "tab" to select built-in file opening.
    Standard Markdown links use [text](url). The plugin also accepts
    (text)[url] as a convenience form inside table cells.

mappings~                              *markdown-table-wrap-mappings*
    Configure or disable Reader and Float buffer-local mappings. Set
    mappings.reader = false or mappings.reader.enabled = false to install no
    Reader-local mappings. Commands and documented <Plug> mappings remain.

    mappings.reader.passthrough explicitly captures a Source mapping. A value
    may name a plugin action such as "next_buffer", or use a table containing
    policy = "leave", "source", or "view". No passthrough is installed by
    default.

    mappings.reader.cell controls Source-aware operations on the logical cell
    under the Reader cursor. Its defaults are yic (raw Source yank), vic
    (logical rendered-cell Visual selection), dic (clear Source content), cic
    (change in Source Insert), c (native Source change-operator proxy), and .
    (cell repeat). put defaults to false so Vim's native cip remains available
    from Reader prose and table cells; set put = "cip" only as an explicit
    compatibility opt-in. Set the cell table to false or { enabled = false }
    to disable these mappings. A cell mutation is restricted to one physical
    Source line; register newlines are flattened to spaces so table row
    structure remains valid. With operator-prefixed yank/delete mappings,
    Reader reserves those first keys and cancels every non-matching suffix;
    use native Visual selection for rendered copy.

    mappings.reader.copy_cell and copy_table optionally install local keys for
    the semantic rendered-cell and complete rendered-table copy actions. Both
    default to false, so no additional Reader key is consumed by default.

    Source editing companion commands do not add default normal-mode keys.
    Their stable actions and <Plug> mappings are documented under
    |markdown-table-wrap-api|. They always leave Reader/Float before a Source
    rewrite and refuse excess-cell tables without partial changes.
>
      mappings = {
        reader = {
          passthrough = {
            H = "previous_buffer",
            L = "next_buffer",
            gf = "open",
          },
        },
      }
<

map_gx~                                    *markdown-table-wrap-map-gx*
    Opt into a buffer-local gx mapping for table links in Source buffers.
    Defaults to false, leaving the user's existing mapping untouched. Reader
    links remain directly openable. |:MarkdownTableOpen| can also be
    mapped manually.

extra_filetypes~
    List of additional filetypes to enable table rendering for. The default
    is {}, meaning the built-in markdown, md, quarto, rmd, and rmarkdown
    filetypes render tables. Example:
>
      require("markdown-table-wrap").setup({
        extra_filetypes = { "text" },
      })
<
    NOTE for LazyVim users: If you add extra filetypes, you must also
    include them in the plugin's ft list to load the plugin for those
    filetypes:
>
      return {
        {
          "ice345/markdown-table-wrap.nvim",
          ft = { "markdown", "quarto", "rmd", "text" },
          opts = {
            extra_filetypes = { "text" },
          },
        },
      }
<

LUA API                                      *markdown-table-wrap-api*

The inspection helpers return effective per-buffer state without changing it.

get_buffer_config({bufnr})~      *markdown-table-wrap.get_buffer_config()*
    Return a deep-copied effective configuration for {bufnr}, including
    runtime view, auto-preview, and inline-viewport overrides. Omit {bufnr} or
    pass 0 for the current buffer.

get_preview_mode({bufnr})~          *markdown-table-wrap.get_preview_mode()*
    Return the effective "reader", "inline", or "float" mode for {bufnr}
    without mutating global setup. Omit {bufnr} or pass 0 for the current
    buffer.

get_state({bufnr})~                        *markdown-table-wrap.get_state()*
    Return a copied active context with mode, canonical Source, view/window,
    mapped cursor, table/cell, cache, and effective configuration. Return nil
    plus an error when the requested view is invalid.

parser.parse_lines({lines}, {opts})~
    Pure line-array API returning Source-spanned table, delimiter, row, cell,
    and inline-token models. parser.parse_all({bufnr}, {opts}) is the thin
    live-buffer adapter that adds Source identity and changedtick caching.

discovery.status({bufnr}) / cache.inspect({bufnr})~
    Return discovery backend/fallback and cache-stage diagnostics without
    changing the active view.

resolve_source_buffer({bufnr})~
                         *markdown-table-wrap.resolve_source_buffer()*
    Return the canonical Source buffer behind Source, Inline, Reader, or
    Float.

action({name}, {opts})~                       *markdown-table-wrap.action()*
    Run a stable mode-agnostic action. Common names are toggle_reader,
    toggle_inline, edit_source, close, refresh, open, open_split,
    open_vsplit, open_tab, next_buffer, previous_buffer, alternate_buffer,
    split_source, vsplit_source, tab_source, inspect, help, copy_cell, put_cell,
    copy_table, export_tsv, export_csv, viewport_left, viewport_right,
    format_table, add_row_table, delete_row_table, move_row_up_table,
    move_row_down_table, add_column_table, delete_column_table,
    move_column_left_table, move_column_right_table,
    toggle_alignment_table, and open_cell_popup_table.

edit_table({action}, {opts})~
    Run one explicit Source editing operation. {action} is one of format,
    add_row, delete_row, move_row_up, move_row_down, add_column,
    delete_column, move_column_left, move_column_right, toggle_alignment, or
    open_cell_popup. Structural rewrites and popup commits each form one undo
    step; rendering never calls this API implicitly.

statusline({bufnr})~                       *markdown-table-wrap.statusline()*
    Return a compact component such as "MTW Reader T3:C2", or an empty string
    for an invalid context.

==============================================================================
HIGHLIGHTS                                  *markdown-table-wrap-highlights*

Highlight groups:

- MarkdownTableWrapBorder
- MarkdownTableWrapHeader
- MarkdownTableWrapInline
- MarkdownTableWrapSource
- MarkdownTableWrapCode
- MarkdownTableWrapBold
- MarkdownTableWrapItalic
- MarkdownTableWrapStrike
- MarkdownTableWrapLink
- MarkdownTableWrapWikiLink
- MarkdownTableWrapImage
- MarkdownTableWrapMark
- MarkdownTableWrapBlank

Semantic highlight groups are reapplied after ColorScheme. A direct custom
spec replaces the preset's linked base for that semantic key.

Content highlight keys are background-transparent when they only link to an
existing highlight group. This prevents Inline replace mode from drawing a
filled rectangle for every cell when a colorscheme gives Normal, Title, or
another linked group a background. Add an explicit `bg` to opt into a filled
background; `blank` is only the padding highlight and can usually be `{}`.

Inline-code delimiters inside link or image labels are removed from the
display text before width calculation. This keeps concealed backticks from
shifting the rendered table separators in Inline mode.

Override by semantic key:
>
  require("markdown-table-wrap").setup({
    highlights = {
      code = { fg = "#9ece6a" },
      bold = { fg = "#e0af68", bold = true },
      link = { fg = "#7dcfff", underline = true },
      mark = { fg = "#1a1b26", bg = "#e0af68" },
    },
  })
<

==============================================================================
LIMITATIONS                                *markdown-table-wrap-limitations*

- Inline replacement uses virtual text and optional virtual lines. These are
  visual rows, not real buffer rows. Use |:MarkdownTableScrollDown| /
  |:MarkdownTableScrollUp| to page through the inline rendered slice, or use
  |:MarkdownTableReader| / |:MarkdownTableFloatPreview| for a normal
  scrollable preview buffer.
- Terminal and platform combinations can differ in how wrap, conceal, and
  virtual text interact. The default
  |markdown-table-wrap-inline-disable-wrap| setting exists to prevent
  concealed long source rows from leaking through below the rendered table on
  some terminal setups. Reader mode avoids this extmark/wrap interaction
  entirely.
- Tree-sitter discovery is optional and diagnostic. Auto intentionally keeps
  the deterministic Lua scanner until measurements justify preferring it.
- Container-prefixed tables nested inside blockquotes or lists are not
  implemented yet. Container starts safely terminate a top-level table.
- The plugin focuses on Markdown pipe tables and does not replace general
  Markdown rendering.
